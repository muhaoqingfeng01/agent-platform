# C4 切片参数配置化实现方案

> **类别**: C | **优先级**: P2  
> **现有代码**: `DocumentPipelineOrchestrator.resolveChunkConfig` 写死 512/50

## 1. 现状与缺口

文档/KB 上的 chunk 配置不生效，策略只吃到默认。

## 2. 解决什么场景

FAQ 用小 chunk，长文用 1024+overlap，按知识库调整。

## 3. 为什么这样设计

优先级：文档 `chunkConfigJson` > KB `chunkSize/chunkOverlap` > 系统默认 512/50。  
解析失败用默认并 warn，不中断管线。

## 4. 技术栈

Jackson；现有 Document/KB 字段。

## 5. 实现方案

```
resolveChunkConfig(doc):
  map = defaults 512/50
  kb = find KB
  if kb.chunkSize != null: put chunk_size
  if doc.chunkConfigJson: putAll parse
  return map
```

策略已 `getInt(config, "chunk_size", 512)`，无需改六策略。

## 6. 流程图

```mermaid
flowchart LR
    DEF["512/50"] --> KB["KB 字段"]
    KB --> DOC["doc.chunkConfigJson"]
    DOC --> SPLIT["strategy.split"]
```

## 7. 验收标准

- 文档 JSON `{"chunk_size":256}` 时切片长度明显变短。  
- 非法 JSON 仍能 PARSED。

## 8. 风险

改参数不自动重切片，需文档说明「需重新解析」。
