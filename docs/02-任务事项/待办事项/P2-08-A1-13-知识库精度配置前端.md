# A1-13 知识库精度配置前端

> **类别**: A | **优先级**: P2  
> **来源已办**: B10（四级 merge 已进检索；KB 精度 JSON 无配置 UI）  
> **关联**: KB/文档字段、`PrecisionController`（评估/优化可选）  
> **依赖**: 现有 `/admin/knowledge`、文档子页

## 1. 现状与缺口

一期仅知识库列表与文档上传；运营无法在 UI 改 searchStrategy / searchParamsJson，B10 合并源缺一层可运营入口。

## 2. 解决什么场景

按库选择 precise/turbo 等策略，或微调 topK/阈值，保存后检索立刻吃到合并结果。

## 3. 为什么这样设计

挂在知识库详情或列表「配置」抽屉，不新开大模块；`PrecisionController` 的 evaluate/optimize 作 **可选高级区**，本项验收以「配置保存 → 检索行为变化」为主闭环。

## 4. 技术栈

扩展 `KnowledgeList` / 新建 `KnowledgeDetail`；Form 绑定 KB 更新 API（以后端实际 update 字段为准）。

## 5. 实现方案

1. 知识库编辑增加：searchStrategy 下拉、searchParamsJson（或常用参数表单生成 JSON）。  
2. 保存后到聊天选该 KB 做知识检索，对比 topK 等是否变化。  
3. （可选）按钮调 `/precision/evaluate` 展示分数，失败不阻断主闭环。  
4. 权限与 `kb:write` 对齐。

## 6. 流程图

```mermaid
flowchart LR
    Form["KB 精度表单"] --> Save["update KB"]
    Save --> Search["知识检索"]
    Search --> Merge["B10 merge 生效"]
```

## 7. 验收标准

- 修改 topK 并保存后，同 query 检索返回条数上限符合配置（在数据足够时）。  
- 非法 JSON 保存失败有明确错误。  
- 只读权限不可改。

## 8. 风险

切片参数硬编码属 C4，本项不承诺 chunk 生效；文案区分「检索精度」与「切片」。
