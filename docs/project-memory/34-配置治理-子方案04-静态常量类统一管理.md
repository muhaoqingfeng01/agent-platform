# 配置治理-子方案04-静态常量类统一管理实现

> **日期**: 2026-07-14 12:30
> **分支**: nacos/nacos-config
> **触发**: 代码生成

## 做了什么

按照设计方案，创建 `ProjectConstants.java` 集中管理静态常量，并改造 26 个文件消除魔法数字：

### 新建文件
- `agent-platform-common/src/main/java/com/example/agent/common/constant/ProjectConstants.java` — 7 个内部类 25 个常量

### 改造文件（26 个）

| 类别 | 文件 | 改造内容 |
|------|------|---------|
| 安全 | `PasswordService.java` | BCRYPT_STRENGTH → `ProjectConstants.Security.BCRYPT_STRENGTH` |
| 业务限制 | `KnowledgeBaseDomainService.java` | MAX_DOCUMENT_COUNT/MAX_FILE_SIZE → `ProjectConstants.BusinessLimit.*` |
| 业务限制 | `DocumentApplicationService.java` | MIN_PART_SIZE → `ProjectConstants.BusinessLimit.MIN_PART_SIZE` |
| API 文档 | `OpenApiConfig.java` | 5 处 URL/Email → `ProjectConstants.ApiDoc.*` |
| WebSocket | `WebSocketConfig.java` | "/ws/conversation" → `ProjectConstants.WebSocket.CONVERSATION_ENDPOINT` |
| RAG 配置 | `RagConfig.java` | 5 处索引兜底值 → `ProjectConstants.IndexBuild.*` |
| RAG 配置 | `RagPrecisionProperties.java` | 9 处索引/检索默认值 → `ProjectConstants.IndexBuild.*` |
| 分页 DTO | 19 个 `*ListRequest.java` | page=0/size=20 → `ProjectConstants.Page.*` |

## 关键决策

1. **IndexBuild 常量同时用于 RagConfig 和 RagPrecisionProperties** — 确保 Nacos 动态配置和 YAML 静态配置的兜底值一致
2. **非标准分页 DTO 部分迁移** — FileListRequest(size=50)、MessageListRequest(size=50)、TicketListRequest(page=1)、EvaluationListRequest(page=1) 仅迁移匹配标准常量的字段
3. **RagConfig.orElse() 改为引用 ProjectConstants** — 让兜底值与 ProjectConstants 保持同步，后续只需改一处
